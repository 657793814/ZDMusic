# B站视频转音频下载机制

## 概述

ZDMusic 可以在 B站 搜索视频，并将视频内容下载到本地转为 MP3 格式播放。本文档解释这一机制的技术原理及相关的法律注意事项。

## 技术原理

### B站视频流结构

B站（以及大多数主流视频平台）的视频在播放时，实际传输的是**两路分离的数据流**：

| 流类型 | 编码格式 | 用途 |
|--------|---------|------|
| 视频流 | .m4v / .flv / .h264 | 画面内容 |
| 音频流 | .m4a / .aac | 声音内容 |

浏览器/播放器端在本地将两路流实时合成，实现音画同步播放。这两路流通过 B站 CDN 分发，**在播放时是公开可拉的**。

### bv2mp3 的工作流程

ZDMusic 使用 `bv2mp3`（npm 包）完成转换，流程如下：

```
B站视频链接
    ↓
① 获取视频信息（API: x/web-interface/view）
   → 解析出视频的 cid、标题等元数据
    ↓
② 获取视频流地址（解析 CDN 链接）
   → 只请求音频流（m4a 或 audio-only 分段）
    ↓
③ 下载音频流 → 保存为原始格式（.m4a）
    ↓
④ FFmpeg 转码 → 输出 MP3 文件
   ↓
⑤ 重命名、打标签、存入曲库目录
```

**关键点：** 工具并非直接下载"一个 MP3 文件"，而是从视频流中**提取并转码**出音频部分。

### 为什么不直接下视频再转？

- 音频流体积远小于视频流（~1/10），下载更快、更省带宽
- 避免下载不必要的画面内容
- 降低对 B站 CDN 的带宽压力

### 与本地模式的关系

```
云端模式（B站搜索）
    ↓ 选择视频 → 转音频
       ↓
    音频存入 MUSIC_DIR/{日期}/ 目录
       ↓
   本地模式可检索到已下载文件
       ↓
    下次直接播放本地文件，无需重复下载
```

一旦转换完成，音频 MP3 文件就保存在本地曲库中（默认 `~/Documents/bili/{YYYYMMDD}/`）。文件名中会附加 `_BV{XXXX}` 后缀以关联原始 B站 视频，用于弹幕加载等后续功能。

## 版权与法律说明

**免责声明：本项目的下载功能仅供个人学习研究使用。**

### 技术层面的公开性

| 条目 | 说明 |
|------|------|
| 视频流是否公开 | ✅ 是的，登录后可正常播放，播放时拉取的 CDN 流是公开的 |
| 是否有 DRM 保护 | ❌ B站大部分内容无 DRM，流地址直接可拉取 |
| B站官方是否提供下载 | ❌ B站没有提供「单独下载音频」的官方接口 |
| 是否绕过付费墙 | ❌ 本项目不处理付费/大会员专享内容 |

### 法律灰色地带

1. **用户协议** — B站 用户协议通常禁止私自下载平台内容（包括视频流）
2. **版权归属** — B站上绝大部分内容（音乐、翻唱、影视原声、课程等）版权归原作者或权利人所有
3. **个人合理使用** — 中国的著作权法并未明确"个人转换格式"是否属于合理使用，但实践中个人自用通常不被追究
4. **传播风险** — 如果转换后的文件被再次分发、传播，构成版权侵权的风险显著提高

### 本项目采用的限制措施

- 未内置批量下载功能，仅支持用户逐首选择
- 文件存储在本地，不提供在线播放给第三方
- 下载内容不重新上传或分发

## FAQ

### Q: B站的音频和视频是分开存的两份文件吗？
A: 不完全对。B站的 CDN 上通常存的是视频容器（如 MP4）内包含的视频轨和音频轨，或者存为独立的多段切片。但可以理解为"流层面是分离的"，播放器会按需拉取音视频两路并合成播放。

### Q: 这些音频是 B站官方提供的吗？
A: 不是。B站并没有"B站音频"独立服务。音频是从视频流中提取出来的。

### Q: 为什么有的视频能转有的不行？
A: 可能的原因：
- 视频使用特殊的封装格式，没有被 bv2mp3 支持的解析器覆盖
- B站 API 接口变动，需要更新 bili.ts 中的签名算法
- 视频本身无音频轨（纯视频/纯字幕类内容）
- B站 安全策略拦截（返回 HTML 反爬页面），需要检查 Cookie 是否有效

### Q: 下载速度慢怎么办？
A: 下载速度受限于 B站 CDN 节点和网络环境。国内用户通常较快，海外用户可能需要代理。
